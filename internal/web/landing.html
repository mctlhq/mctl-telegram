mctl-telegram MCP

Remote MCP server that exposes your Telegram user-account to Claude.ai and other MCP clients. Five tools: list dialogs, read unread, read by peer, send draft/live, pin/unpin.

MCP endpoint
{{.MCPURL}}
Streamable HTTP — works via POST with Accept: application/json, text/event-stream. Opening it in a browser shows this page; that is expected.
What this is — and what it isn't.

mctl-telegram holds a server-side Telegram MTProto session on your behalf. This is not a zero-knowledge service. The server can technically read your Telegram data while processing your requests, because it is the one making MTProto calls to Telegram. We minimize what is stored (encrypted session blob only) and what is logged (no message text, no phone numbers), but you are trusting both the operator of this deployment and the integrity of this code.

See /security for the full threat model and /privacy for the data inventory and retention policy.

1. Add as a custom connector in Claude.ai

  1. Open claude.ai → Settings → Connectors and click Add custom connector.
  2. Paste the Remote MCP URL: {{.MCPURL}}
  3. Authentication: OAuth. Claude.ai discovers the authorization server from the well-known document at {{.WellKnownURL}} and redirects to {{.AuthServer}} for GitHub login.
  4. Sign in with the GitHub account that has access to your mctl tenant. The issued JWT is verified by mctl-telegram via shared HMAC.

2. Available tools

ToolAnnotationScope requiredNotes
list_dialogs read telegram:dialogs:read Inputs: limit (≤200, default 50), optional query.
get_unread_messages read telegram:messages:read Inputs: optional peer, limit (≤200).
get_messages read telegram:messages:read Full history of a specific peer, not just unread.
send_message write telegram:messages:send Default mode=draft returns a dry-run preview. Real send requires all of: server ALLOW_SEND=true, identity scope, per-account send_enabled=true, and mode=send.
pin_message write telegram:messages:pin Inputs: peer, message_id, unpin (bool).
disconnect_telegram_account write any authenticated identity Soft-revokes your session — see Your controls.
delete_telegram_account write any authenticated identity Hard-deletes the encrypted session blob.

4. What we store

RowContentsRetention
users github_login, optional email Until you call delete_telegram_account (cascades).
telegram_accounts.session_encrypted AES-256-GCM-sealed MTProto session blob, per-user HKDF-derived key Until you call disconnect (marked revoked) or delete (row removed).
audit_logs tool name, redacted peer reference, status, error. Never the message body, phone number, or session bytes. Retained indefinitely today; 90-day sweeper is planned (M2). Ask the operator if you need an earlier purge.

5. Your controls

  • Disconnect (soft): call MCP tool disconnect_telegram_account, or POST /api/account/disconnect. Marks the session revoked and immediately tears down the in-memory MTProto client.
  • Delete (hard): call MCP tool delete_telegram_account, or DELETE /api/account. Removes the encrypted session blob and all per-account metadata.
  • Status: GET /api/account returns connection state, display name, and the per-account send_enabled flag.
  • Revoke from Telegram's side: Telegram app → Settings → Devices → close the session named after this app. This will not delete data here but will sever the MTProto link Telegram-side.

6. Smoke-test from your terminal

Confirm the well-known and a JSON-RPC handshake before adding the connector:

curl -s {{.WellKnownURL}}

curl -s -X POST {{.MCPURL}} \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"smoke","version":"0"}}}'

7. First-time Telegram login

Until an in-browser /telegram/connect flow ships, the operator runs the CLI binary mctl-telegram-login bundled in the same image. It performs phone → SMS code → optional 2FA password and persists an AES-256-GCM-encrypted MTProto session keyed to your GitHub login. The full recipe lives in the repo README. Self-service flows are tracked in the roadmap.
