mctl-telegram MCP

Remote MCP server that exposes your Telegram user-account to Claude.ai and other MCP clients. Tools: list dialogs, read unread, read by peer, send draft/live, pin/unpin, audit log, disconnect/delete.

MCP endpoint
{{.MCPURL}}
Streamable HTTP — works via POST with Accept: application/json, text/event-stream. Opening it in a browser shows this page; that is expected.
What this is — and what it isn't.

mctl-telegram holds a server-side Telegram MTProto session on your behalf. This is not a zero-knowledge service. The server can technically read your Telegram data while processing your requests, because it is the one making MTProto calls to Telegram. We minimize what is stored (encrypted session blob only) and what is logged (no message text, no phone numbers), but you are trusting both the operator of this deployment and the integrity of this code.

See /security for the full threat model and /privacy for the data inventory and retention policy.

1. Add as a custom connector in Claude.ai

  1. Open claude.ai → Customize → Connectors and click Add custom connector.
  2. Paste the Remote MCP URL: {{.MCPURL}}
  3. Authentication: OAuth. Claude.ai discovers this server as its own authorization server via the well-known documents at {{.WellKnownURL}} and {{.AuthServer}}/.well-known/oauth-authorization-server.
  4. You will see a “Connect Telegram to Claude” page with a Telegram Login Widget. Click it, confirm the login in your Telegram app, and you are signed in.
  5. Message access (read/send) is granted by the encrypted MTProto session stored on this server. If the account is not yet provisioned, the connect screen explains the next step.

3. Scopes and permissions

Scopes are derived from your Telegram identity. Operators on the admin allowlist (TG_LOGIN_ADMINS) get the full platform-admins set. Everyone else gets the client tier — the telegram:* tool scopes for their own account, without platform-admin capability. When AUTO_APPROVE_CLIENTS is enabled (open registration) every signed-in user is a client automatically; otherwise the client tier comes from the TG_LOGIN_CLIENTS allowlist or an operator grant. An operator can revoke any user with set_telegram_access.

Telegram identityScopes granted
Telegram id ∈ TG_LOGIN_ADMINSall telegram:* scopes plus admin:users
Telegram id ∈ TG_LOGIN_CLIENTStelegram:* scopes (dialogs/messages read, send, pin) — no admin:users
Any other authenticated Telegram idnone — every tool call returns 403 until the operator opts you in

For backward compatibility the server can still be run under AUTH_MODE=shared-hmac-legacy, in which case the original GitHub-group→scope mapping applies. The default mode is local-jwt.

4. What we store

RowContentsRetention
users telegram_login_id, telegram_username, telegram_display_name (synthetic github_login=tg:<id> kept for legacy joins). Legacy rows may still carry a real github_login. Until you call delete_telegram_account (cascades).
telegram_accounts.session_encrypted AES-256-GCM-sealed MTProto session blob, per-user HKDF-derived key Until you call disconnect (marked revoked) or delete (row removed).
audit_logs tool name, redacted peer reference, status, error. Never the message body, phone number, or session bytes. Retained indefinitely today; 90-day sweeper is planned (M2). Ask the operator if you need an earlier purge.

5. Your controls

  • Disconnect (soft): call MCP tool disconnect_telegram_account, or POST /api/account/disconnect. Marks the session revoked and immediately tears down the in-memory MTProto client.
  • Delete (hard): call MCP tool delete_telegram_account, or DELETE /api/account. Removes the encrypted session blob and all per-account metadata.
  • Status: GET /api/account returns connection state, display name, and the per-account send_enabled flag.
  • Audit log: get_my_audit_log MCP tool or GET /api/account/audit — newest-first, RFC3339 before cursor for keyset pagination.
  • Verify your audit chain: GET /api/account/audit/verify recomputes the SHA-256 hash chain over your rows and reports {ok, verified} or {ok:false, first_bad_id, reason}.
  • Revoke from Telegram's side: Telegram app → Settings → Devices → close the session named after this app. This will not delete data here but will sever the MTProto link Telegram-side.

7. First-time Telegram login

Sign-in via the Claude.ai connector authenticates you with the Telegram Login Widget. If the server has no MTProto session for your account yet, the connect flow continues straight into an in-browser “Enable message access” step: enter your phone number, type the login code Telegram sends you, and — if your account uses it — your two-step verification password. The server then persists an AES-256-GCM-encrypted MTProto session keyed to your Telegram identity, and the connector is ready — no operator CLI step required. The bundled mctl-telegram-login CLI remains available for operators as a fallback. Full details in the repo README.
