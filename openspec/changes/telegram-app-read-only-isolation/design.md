# Isolated read-only MCP Apps profile design

Apply the named decision at the shared tool registration boundary in `internal/mcp/server.go`. Retain the SDK's existing per-caller discovery and invocation scope filter. Validate the new mode explicitly and fail closed when its safety prerequisites conflict. Keep the reviewed tool set in version-controlled server code. Add a guard that fails if any registration bypasses the common boundary or the effective inventory drifts.

Review the initial read inventory by name: `list_dialogs`, `list_folders`, `list_topics`, `get_unread_messages`, `get_messages`, `search_messages`, `get_my_send_status`, and `get_my_audit_log` if its filtered own-account projection is required and approved. Allow only built-in template reads if the prerelease host pass needs the template prototype, and keep template mutation absent even with dialogs read scope. Add `telegram_dashboard` only after #1482 is reviewed and integrated. Verify every admitted handler and optional argument, including media downloads, against the isolated data boundary and keep optional bulk/media branches disabled if outside the test scope.

Use tests for the isolated HTTP transport and OAuth identity with a separate datastore and synthetic accounts. Install a separate server with `AUTH_REQUIRED=true`, `ALLOW_SEND=false` and `MCP_APPS_ENABLED=true` only after the reviewed boundary is ready. Reuse the existing OAuth client scope ceilings where they cover the isolated registrations. Constrain effective grants to the required read scopes on initial authorization and refresh, including clients that omit an explicit scope. Deny unreviewed registration paths or enforce the read ceiling for them. Ensure issuer, audience, keys, sessions, Telegram fixtures and data source cannot select production resources. Any necessary onboarding or credential setup happens through a separately reviewed operator route. Exclude admin, worker and bridge surfaces and validate all reachable aliases. For the shared Portal, existing tool policy stays intact.

Treat transport logs as identifiers and outcomes only. Keep audit and current scope and OriginGuard checks. Record independent findings with their resolution before owner approval. Roll back isolation by revoking grants and removing its routes and resources through the approved lifecycle.
