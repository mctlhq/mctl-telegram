# Telegram Workspace opener design

Use the existing Go MCP server and resources. Reuse bounded dialog, unread, folder, message, search and own-account read logic. Extract shared internal reads only where needed for the snapshot and preserve per-caller authorization, audit, hidden-chat and broadcast policies. Request identity comes from the authenticated context. The opener has no identity selector. Keep results bounded and return per-section status, server timestamp and the scope or completeness of counts. Add the tool to scope and class maps and give it an explicit Portal decision.

Reuse the template dashboard layout, styles and rendering components and the Triage context and search interactions. The first release uses a fixed Workspace layout with no template editor or action controls. Overview uses authorized sampled dialogs and folders. Inbox filters on chat type and folder and fetches bounded history on selection. Search delegates to `search_messages` with selected peer/topic and UTC dates where available, groups messages by source, and reads context on demand. Use canonical peer and message references. Account status reuses `get_my_send_status` and a minimal authorized own-account projection. Expose own audit data only through a reviewed projection. Show unavailable fields explicitly and omit prioritization from this slice.

Implement the stable SEP-1865 lifecycle and remove dependency on iframe `tools/list`. Read the standard opener result, handle host context, size, teardown and display modes, and route refresh through the same opener read contract. Consume structured results by a versioned shape and ignore stale refresh responses. Evaluate the official MCP Apps SDK against a pinned reference host and the existing bridge. Bundle the SDK inline if it is the smallest maintainable way to meet the lifecycle contract and pass CSP and source checks. Keep the immediate-parent check and empty external origin lists. Keep raw Telegram contents out of model-context updates and diagnostic traces.

Publish a versioned Workspace URI with the exact HTML digest and keep legacy prototype URIs governed by compatibility. Coordinate metadata, resource publication and documentation in one change. Host adapter metadata requires evidence and a focused contract review. Rollback uses the prior reviewed release artifact and connector recreation steps if stale descriptors persist.
